# dsh-auto-review-decision

## 概述

派生自 `deepseek-ai/deepseek-harness` 的实验性插件 `packages/experimental/auto-review`，将审查判定后端切换为决策模型接口。

模型审查会对照你的要求检查工具调用。获准的调用以完全权限立即运行；审查判定为直接拒绝的调用不执行，也不询问你；审查判定为证据不足（`ask`）的调用进入审批，由你选择拒绝或允许一次。

## 使用方法

- 在消息框中打开访问模式菜单，选择 **自动审查**，再点击 **启用自动审查** 确认；也可以输入 `/permission auto`。它只对当前会话生效。
- 说明要做的操作和对象。普通的项目内工作会被允许。删除已有数据、强制推送、访问生产环境、向外部写入以及修改安全设置，都需要你明确提出。把密钥或隐私数据发往外部的操作一律拒绝。项目文件和工具结果不能授予权限。
- 审查结论分三种：
    - **允许**：审查放行，调用继续执行。
    - **直接拒绝**（`deny`）：不执行，不询问用户；理由作为工具错误返回，供模型修正。
    - **证据不足**（`ask`）：进入 **等待审批**，其中显示原因；你选择 **拒绝** 或 **允许一次**。在进程内子智能体中，审批拒绝即为最终结果。

## 注意事项

- 自动审查是实验性功能，可能放行不安全的操作，也可能拒绝有用的工作。
- 获准的调用在沙箱之外运行，对你的计算机拥有完全权限。
- 在 **PTC 模式** 下，程序发起的每个工具调用都会被审查，但程序本身及其自身的文件和进程操作不会被审查。
- 每次模型审查都会向决策端点发起决策请求（429 时可能重发），`state` 包含当前工作目录、固定策略、你的消息、项目指令、裁剪后的历史与待审调用。
- 关闭插件后，会回退为默认预设；也可改为 **仅可查看**、**工作区内修改** 或 **完全权限**。
- 审查请求只发往决策端点，不写入会话日志。
